# qlive-doc

Framework-user documentation for QLive, built with
[Astro Starlight](https://starlight.astro.build) and published to GitHub
Pages at <https://quinscape.github.io/qlive-framework/>.

The pages themselves are plain Markdown in `src/content/docs/`. Everything
else here is the site build.

```bash
pnpm -C qlive-doc install     # once -- see "outside the workspace" below
pnpm docs:dev                 # dev server with hot reload
pnpm docs:build               # static build into qlive-doc/dist
pnpm docs:preview             # serve that build locally
pnpm -C qlive-doc palette     # regenerate src/styles/qlive.css
```

## Outside the pnpm workspace

`qlive-doc` carries its own `pnpm-workspace.yaml`, which makes it a
workspace root of its own rather than a package of the repository's. That is
deliberate: the docs toolchain is ~270 packages and ~220 MB that the Java
build, the framework packages and CI have no use for, so it installs only
when someone actually builds the docs. It is not a Maven module either.

The cost is one extra `pnpm -C qlive-doc install` before the first
`pnpm docs:dev`.

## Colours

`src/styles/qlive.css` is generated -- do not edit it. The six brand colours
live in `tooling/palette.mjs`, which derives every shade, tint and neutral
from them and picks how far to mix by measuring WCAG contrast rather than by
eye. Change a colour there and run `pnpm -C qlive-doc palette`.

## Writing a page

Add a Markdown file to `src/content/docs/` with frontmatter:

```markdown
---
title: Query documents
description: Paging, sorting, update(), and the server-side query.
sidebar:
  order: 7
---
```

`sidebar.order` is what places it; the sidebar is autogenerated, so there is
nothing to edit in `astro.config.mjs`. Link between pages with a route, not
a file name -- `[injections](../injections/)`, not `injections.md`.
